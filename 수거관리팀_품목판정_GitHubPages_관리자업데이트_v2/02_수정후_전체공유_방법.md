# 사이트에서 수정한 내용을 모든 직원에게 반영하기

핵심은 딱 하나입니다.

> 사이트에서 `items.json` 다운로드 → GitHub의 `data/items.json`을 새 파일로 덮어쓰기

## 1. 사이트에서 수정
1. 오른쪽 위 **관리자 편집**
2. 신규 등록 / 수정 / 삭제
3. 작업이 끝나면 **게시용 data.json 받기**
4. 다운로드 폴더에 `items.json`이 생깁니다.

### 새 사진을 등록한 경우
걱정하지 않아도 됩니다.
새로 등록한 사진은 크기를 줄여서 `items.json` 안에 같이 들어갑니다.
따라서 **사진파일을 GitHub에 따로 올릴 필요가 없습니다.**

## 2. GitHub에 새 items.json 올리기
1. GitHub에서 `item-archive` 저장소 열기
2. `data` 폴더 클릭
3. 오른쪽 위 **Add file → Upload files**
4. 방금 받은 `items.json`을 끌어다 놓기
5. 기존 `items.json`과 같은 이름이므로 변경 파일로 잡힙니다.
6. 아래 **Commit changes** 클릭

## 3. 기다리기
GitHub Pages가 자동으로 새 사이트를 만듭니다.
보통 1~3분 정도 후 사이트에서 `Ctrl + F5`로 새로고침하면 됩니다.

업로드한 게시본의 revision이 현재 PC 수정본과 같으면 사이트가 임시 수정본을 자동으로 정리합니다.

## 수정하다가 잘못한 경우
사이트 왼쪽의 관리자 편집 영역에서 **게시본으로 되돌리기**를 누르면,
GitHub에 마지막으로 올려둔 내용으로 돌아갑니다.

## 다른 PC에서 이어서 수정해야 하는 경우
현재 PC에서 **게시용 data.json 받기** → GitHub에 먼저 반영한 뒤 다른 PC에서 수정하는 것을 권장합니다.
또는 관리자 영역의 **data.json 불러오기**를 이용해 파일을 직접 불러올 수 있습니다.

## 주의
GitHub Pages는 DB가 아닙니다.
두 사람이 서로 다른 PC에서 동시에 수정하면 마지막에 GitHub에 올린 `items.json`이 최종본이 됩니다.
따라서 수정 담당자는 한 번에 한 명으로 정하는 것이 가장 안전합니다.
